# 결정 기록 (문서에 없던 세부 결정)

## 6장 기본값 적용
- 블라인드 "24 48" → 2/4, 4/8 두 레벨 / 앤티는 10/20부터 BB의 절반 / 레벨 시간 3·5·8·10·15분(기본 5분)
- 체크·콜은 베팅 버튼에 통합 / 리엔트리·ICM 없음(chipEV) / 칩 ×100 / AI 카드 전체 공개는 토너먼트 종료 후
- 파일 내보내기는 핸드 사이에만 / BB 칩 부족 시 앤티 먼저, 남은 칩으로 블라인드 / 배포 안 함
- 단순 기억 반응 넣음(설정에서 끌 수 있음) / 칩 색 2.13 표 / 닉네임 무작위·성향 무관

## 엔진
- 난수: 핸드 시드(128비트)는 `crypto.getRandomValues`, 셔플은 그 시드로 만든 xoshiro128** + Fisher–Yates. 시드만 있으면 핸드 재현 가능. Math.random 미사용.
- 핸드 평가기: 직접 구현(랭크/수트 비트마스크). 외부 패키지·라이선스 없음.
- 불완전 올인 규칙: "마지막으로 행동했을 때의 베팅 수준 대비 완전한 레이즈 이상을 받았는가"로 판정 → 여러 번의 불완전 올인이 합쳐 완전한 레이즈가 되면 다시 열림(TDA와 같은 방향).
- BB 앤티는 '데드 머니'로 메인 팟에 들어감(라이브 벳·사이드팟 계산에서 제외, 모두가 다툼).
- 콜되지 않은 벳은 스트리트 종료 시 돌려줌.
- 남는 칩 단위 = 100(가장 작은 칩).
- 블라인드를 내다가 전원 올인이 되는 등 행동할 사람이 없으면 엔진이 바로 런아웃·쇼다운까지 진행.
- 쇼다운 공개: 올인 런아웃이면 전원 공개, 아니면 순서대로 '지금까지 공개된 최고 패 이상이거나 승자'만 공개(나머지는 머크).
- 사람이 탈락하면 남은 AI끼리 진행하지 않고 토너먼트 종료(포기와 같은 방식). 결과 화면에서 남은 AI는 "생존 + 칩"으로 표시.

## AI (v1)
- 169핸드 순위: 0.5×랜덤 핸드 상대 에퀴티 + 0.5×상위 25% 상대 에퀴티 (scripts/generate-hand-rank.ts, 몬테카를로)
- 오픈 %는 "내 뒤에 남은 사람 수"로 6/8/10인 표를 하나로 합침 (config.ts `openPctByBehind`)
- 푸시/폴드 근사: 10BB 앵커 × (10/유효BB)^0.75 (검증 안 됨, v2에서 내시 표로 교체)
- 레인지 추적: "평균적 플레이어" 우도 함수(프리플랍 시그모이드, 포스트플랍 강도 백분위·드로우)로 베이즈 갱신. 특정 상대 통계는 쓰지 않음.
- 에퀴티: 리버 헤즈업은 전수, 나머지는 가중 레인지 몬테카를로(정상 1200 / 빠른 250회). 상대 강도 10버킷으로 '콜 레인지 상대 에퀴티'를 한 번에 계산.
- 실력 레벨이 정하는 것: 실수 온도(균등 분포 혼합), EV 소프트맥스 온도, 상대 레인지 반영 비율(Lv1–3 0 = 내 패만 봄 → Lv9+ 1), 팟오즈 감각 오차, 푸시 범위 오차, 사이즈 실수, 감정 배수, 릭 개수·강도.
- 피쉬 상한 때문에 레벨 균등 배정이 깨지는 경우(예: 보통 6명 AI) Lv4를 Lv5로 올려 맞춤.
- 드라이 보드 헤즈업 PFR은 레인지 전체로 작게 C벳(IP 75%, OOP 50%) — 시험지 문항을 통과시키려고 추가.
- AI 판단 메모: 각 결정의 PlayerView도 함께 저장(신고 재현용). 용량이 커지지만 IndexedDB라 감당 가능.
- "내 결정 비교(AI 기준)": 내 차례마다 솔버 Lv10 프로필로 계산해 기록만 함(화면 표시는 다음 단계).

## UI
- React + Zustand, CSS만 사용(애니메이션은 CSS transition). 4색 덱(♦ 파랑, ♣ 초록)으로 수트 구분.
- 빠른 베팅 버튼(1/3·1/2·팟)은 문서대로 기본 없음(슬라이더 + −/+).
- 폴드: 체크 가능할 때는 한 번 더 눌러야 폴드. 올인: 한 번 더 눌러 확정.
- 좌석: 화면 좌표에서 시계 방향 = 아래→왼쪽→위→오른쪽. 내 자리(좌석 0) 항상 하단 중앙. 탈락해도 자리를 당기지 않음.
- 개발 모드에서만 `window.__store` 노출(Playwright 점검용).
- 한글 폰트는 시스템 폰트.

## 2026-11-25 사용자 결정
- 딜러 버튼(D) 표시 삭제: 모바일에서 겹침이 심함. 버튼 위치는 엔진 내부에서만 쓰고(데드 버튼 규칙 그대로), 화면에는 표시하지 않음. SB/BB는 블라인드 칩·말풍선으로 보임.
- 올인 삼각형 토큰 삭제: 올인은 효과만 유지(이름표 빨간 번쩍임, 스택 자리 'ALL-IN', '올인 콜' 말풍선, 올인 쇼다운 공개 핸드 빨간 테두리).
- 딜러 버튼 재도입(같은 날): 테이블 위에 떠 있는 버튼 대신 버튼 자리 이름표 오른쪽 위 모서리에 작은 'D' 배지. 자리 상자 안에 붙어 있어 다른 요소와 겹치지 않음. 데드 버튼이면 빈자리 상자에 표시.

## 2026-11-25 AI v2 방향 전환 (사용자 결정)
- 레벨 간 실력 차이를 칩 대결로 맞추는 것은 목표에서 내림. 최우선은 **짧게 쳐 봤을 때 맞는 행동·강한 플레이가 자주 보이는 것**.
- 명확한 자리(보는 사람이 한눈에 정답을 아는 자리)에서는 레벨·성향과 상관없이 정답만 한다 (`src/ai/v2/clarity.ts`). 판별은 족보·가격 같은 객관 사실로만.
- 실력 차이는 무작위 흐림 대신 '이름 붙은 구멍(릭)' 개수로: 구멍은 자기 자리에서 거의 매번 나와 찾아낼 수 있게. 릭이 명확한 자리에서 발동하면 그 구멍은 일부러 남김.
- 압박 자리(강한 패 3벳·체크 받은 강한 패 밸류·젖은 보드 몬스터 레이즈)는 최소 비율 보장. 피쉬 성향은 수동적인 게 특징이라 60%만.
- 평가 기준: `scripts/ai-clarity-report.ts`의 명확한 자리 정답률·압박 자리 실행률을 우선으로 보고, `ai:match`는 퇴보 확인용으로만 씀.
- (마일스톤 7) 레벨 차이를 짧은 테스트에서 보이게 하는 두 번째 축: **일관성**. 고수(Lv6+)는 확률을 날카롭게 해 우세한 행동을 꾸준히, 하수는 흐트러진 채로. 모든 레벨에서 7% 미만 행동은 고르지 않음(사람 눈에 '이상한 플레이'로 보임).
- v2 전용 조정값은 config(`AI.personaV2`, `evCutMinV2`, `tailCutV2`, `sharpenV2`, `threeBetMultV2`)에 둔다. personas.json과 `AI.guards`는 v1 기준선과 공유하므로 v2 때문에 바꾸지 않는다.

## 2026-11-26 AI v3 시작 (사용자 결정)
- v1 코드 삭제(기준선 역할은 v2가 넘겨받음). 루트의 overview 사본(`holdem_pub_ai_overview.md`, docs/overview.md와 동일) 삭제. 공용 계산은 `src/ai/core`로.
- v3는 '사람이 포커 칠 때 떠올리는 개념'을 모듈로 계산하고, 레벨은 **어떤 개념을 보느냐·얼마나 정확히 보느냐**로 나눈다. 일부러 틀리게 만드는 릭·습관 체계는 v3에서 일단 보류.
- 플레이 스타일(타이트/루즈, 공격/수동, 블러프 빈도 등)은 실력 표준을 먼저 만든 뒤 나중에 얹는다.
- 개발·평가는 게임 화면이 아니라 AI 전용 대결장(`scripts/ai-arena.ts`)에서. 생각 과정 기록을 Sonnet 리뷰어(노력 중간)에게 고수 입장으로 검토시키고 모듈을 고치는 루프를 돈다.
- 판단 시간 목표: 결정당 평균 수 ms, 최대 100ms 이하 (리버 솔버 40ms 상한).
- 고수 v3는 '평균적인 사람' 모델 대비 약간의 착취를 한다(리버에서 사람들이 블러프를 덜 섞고 덜 접는 경향: `AI_V3.solverCallScale`·`solverBluffScale`·`bluffMult.river`). 상대 기억은 쇼다운으로 본 것만.

## 2026-11-27 AI v3 마일스톤 4
- 리버 벳 레인지 속 블러프 추정 22% → 10% (작은 벳 ×1.6, 오버벳 ×0.8). 근거: 같은 시드 비교에서 Lv8 vs v2 헤즈업 +4.5 → +14.3, 링 +0.6 → +10.5(값 8% 기준). 사람(특히 하수~중수)이 리버에서 블러프를 덜 섞는다는 경향. 너무 잘 접히는 상대가 되지 않게 8%보다 조금 높은 10%로, Lv7+는 쇼다운 기억으로 상대별 재조정.
- 리버 솔버는 유지: 끄기·벳 받을 때만·먼저 행동할 때만 4가지를 2만 쌍씩 비교해 모두 노이즈 범위(±10bb) 안.
- 초급 레벨 차이 = 새 개념 하나씩: Lv2 '큰 벳 경계'(`AI_V3.from.bigBetFear`), Lv3 '레이즈는 강하다'(lineBasic 4→3)·매몰 비용 심리 없음·시작 패 고르기. 레벨 차이는 헤즈업이 아니라 6인 링으로 잰다.
- 생존 프리미엄은 스택 비율로 연속(내가 1칩 더 많아도 지면 거의 다 잃으면 부담은 같음). 60BB 이상이면 '누가 나를 커버하나' 표시 안 함.
- 스타일은 확률만 민다(개념을 끄지 않음). 같은 스타일도 레벨이 높을수록 축 ×0.6(중급 ×0.8). 앱 배정 시 'standard'는 스타일 없음으로 저장(예전 저장과 같은 모양).

## 2026-11-27 최고 레벨 상황별 개선 (마일스톤 5)
- 최고 레벨 성능은 `scripts/ai-situations.ts`로 잰다: 고정 상대(v2) + 같은 카드·자리 기준 봇(v2 솔버 Lv10)과의 차이. 상대가 코드 변경에 따라 바뀌지 않게 v2만 상대로 둠.
- 리뷰어는 기존 `poker-reviewer`(Sonnet, 노력 중간): 핸드 기록 판정에 충분하고 Opus보다 싸다. 기록은 주인공 결정만 자세히, 쓰레기 패 폴드는 뺌(토큰 절약), 상황 묶음별로 2명 병렬.
- 리뷰어의 '상대 유형별 착취(매니악·바위 구분)' 제안은 받지 않음 — 사람 분석 착취는 하지 않는다는 기존 결정 유지.
- 헤즈업(2명 남음)은 생존 프리미엄 0 (칩 가치 = 생존 가치).

## 2026-11-27 쇼다운 순서 공개·muck 연출, 쇼다운 기억 삭제
- 올인 없는 쇼다운은 `showOrder`대로 한 명씩 공개하거나 muck (간격은 `Table.tsx timings()`의 showStep·showTail). 올인 쇼다운은 지금처럼 동시 공개.
