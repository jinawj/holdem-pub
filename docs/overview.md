## ▶ Claude Code 실행 지시 (이 절을 가장 먼저 읽을 것)

사용자가 "이 문서대로 만들어 줘", "실행해", "프로토타입 만들어" 같이 짧게만 말해도, **추가 질문 없이** 아래 순서대로 프로토타입을 끝까지 만든다.

### A. 시작 전 준비

1. `docs/PROGRESS.md`가 있으면 먼저 읽는다. 끝난 단계는 건너뛰고 거기서부터 이어서 한다. (세션이 끊겼다가 "이어서 해 줘"로 다시 시작한 경우)
2. 이 문서가 `docs/overview.md`에 없으면 그 경로로 복사한다.
3. Node.js(LTS)와 npm을 확인한다. 현재 폴더에 프로젝트를 만든다. git 저장소가 아니면 `git init`.
4. 1.6절 내용으로 `CLAUDE.md`를 만든다.

### B. 결정 규칙

- 문서의 **[확인 필요]** 항목은 전부 **6장 '프로토타입 기본값'**으로 진행한다. 사용자에게 묻지 않는다.
- 문서에 없는 세부 결정(색, 애니메이션, 라이브러리 선택 등)은 합리적으로 정하고 `docs/DECISIONS.md`에 한 줄씩 기록한다.
- 구현이 막히면 멈추지 말고, 가장 단순한 방식으로 먼저 동작하게 만든다. 그리고 `docs/PROGRESS.md`의 '알려진 문제'에 적는다.
- **AI 우선 원칙**: 이 프로젝트에서 가장 공들이는 부분은 AI다(3.13). 노력 배분은 **AI와 AI 평가 체계 > 엔진 규칙의 정확성 > UI 꾸미기** 순서. UI는 기능이 다 되고 깔끔하면 충분하다.
- 사용자에게 묻는 건 두 경우뿐이다.
  - 현재 폴더에 이 게임과 무관한 기존 코드가 있어서 덮어쓸 위험이 있을 때
  - 설치·실행 환경 문제로 진행이 아예 불가능할 때
- Playwright 브라우저 설치처럼 환경 때문에 안 되는 **부가 작업**은 건너뛰고 마지막 보고에 적는다.
- 튜닝할 숫자(오픈 %, 임계값, 성향 파라미터, 고민 시간 등)는 문서 값을 쓰되, 코드 곳곳에 흩지 말고 **설정 파일 한 곳**(`src/data/*.json` 또는 `src/config.ts`)에 모은다.
- 핸드 평가기는 라이선스 문제를 피하려고 직접 구현한다(비트마스크 방식 등). 외부 패키지를 쓰면 라이선스를 `DECISIONS.md`에 기록한다.

### C. 프로토타입 범위

**포함 (필수)**
- 1장: Vite + TypeScript + React, 반응형(세로/가로), 기본 PWA 설정, 1.4 함정 체크리스트 중 필수 항목(`100dvh`, safe-area, `touch-action`, `overscroll-behavior`, `user-select`)
- 2장 전부: 설정 화면(인원·시작 스택·레벨 시간·AI 속도·난이도), 칩 ×100 표기, 블라인드 표(JSON), 무작위 셔플·첫 버튼, D 버튼만 표시, 2.6 규칙 전부, 슬라이더·−/+·베팅/폴드/올인, 남은 시간·일시정지, 자동 저장·이어하기, 파일 내보내기/불러오기, 모든 핸드 기록, 게임 포기, 지금 핸드 강조하기, 결과 화면, **팟·베팅 칩 그림과 칩 이동 애니메이션(2.13)**, **AI 닉네임(2.14)**
- 복기: 결과 화면 → "강조한 핸드 N개 복기하기", 리플레이어(한 액션씩 앞/뒤, 강조한 순간부터 열기), 필터(강조 / 내가 참여 / 올인), AI 카드 공개 규칙(토너먼트 종료 후 전체)
- 3장: PlayerView 공정성 구조, Web Worker, 프리플랍(3.4, 푸시/폴드는 근사), 포스트플랍(3.5의 레인지 추적·에퀴티·레인지 백분위 + MDF·블러프 비율·텍스처 사이즈), 성향 7종 + **실력 레벨 Lv1~10과 난이도 3단계(레벨 고르게 배정, 피쉬 수 상한)**(3.6), 온도·틸트(단순형)·고민 시간·금액 반올림(3.7), **안전장치 3.12 전부**, AI 판단 메모 기록
- 셀프플레이 시뮬레이터 기본형(3.11): 빠른 모드(몬테카를로 샘플 축소), 최소 5,000핸드
- AI 평가 체계 기본형(3.14): AI 시험지 30문항 이상, 듀플리케이트 대결, 복기 화면의 "이 AI 행동 이상함" 신고 버튼과 신고 내보내기, AI를 화면 없이 돌리는 CLI
- AI는 버전 폴더로 관리(`src/ai/v1/`). v2 이후는 이 구조에 추가

**제외 (다음 단계, `PROGRESS.md`에 남은 일로 적기)**
- 상대 착취는 프로토타입뿐 아니라 **전체 범위에서 제외**(3.8). 통계는 복기용으로만 수집

- ICM, 버릇(텔), 리엔트리, 텍스트 핸드 히스토리, 내 통계 화면, 핸드 메모, PC 단축키, Wake Lock, 컬러업 연출, 배포

## 0. 한 줄 요약

혼자 하는 **싱글 테이블 노리밋 홀덤 토너먼트**(홀덤펍 방식). **나는 테이블 한 자리에 직접 앉아서 플레이**하고, 나머지 자리는 전부 성향이 다른 AI. 칩은 진짜 칩처럼 100·1,000 단위로 쓰고, 정해진 시간마다 블라인드가 오른다. 웹앱 하나로 **모바일과 PC에서 모두** 돌아간다. 가장 중요한 부분은 **AI 의사결정**이다(3장).

## 1. 플랫폼과 구성 방식 [확정: 모바일·PC 둘 다]

### 1.1 결론: 반응형 웹앱(PWA) 하나

| 방식 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **반응형 웹앱 + PWA** | 코드 하나로 폰·PC 브라우저 모두 실행, 홈 화면 설치, 오프라인 실행, 앱스토어 심사 없음, 무료 배포 | 브라우저별 차이(특히 iPhone Safari) 대응 필요 | **채택** |
| 네이티브 앱 (iOS·안드로이드 따로) | 성능·기기 기능 최고 | 코드 2~3벌, 스토어 등록 비용·심사, PC용 따로 | 과함 |
| Flutter / React Native | 앱 하나로 iOS·안드로이드 | PC 브라우저 쪽이 부차적이거나 무거움, 이 게임엔 이점이 적음 | 불필요 |
| 데스크톱 앱 (Electron 등) | PC 설치형 | PWA로 PC에도 설치 가능 | 불필요 |

- "모바일 모드 / PC 모드"를 따로 만들지 않는다. **화면 비율에 따라 한 화면이 알아서 바뀌는** 방식(1.3).
- 나중에 앱스토어에 올리고 싶어지면 같은 웹 코드를 Capacitor 같은 도구로 감싸면 된다. 처음부터 다시 만들 필요 없음.
- 서버 없는 정적 사이트. 게임·AI·저장 전부 기기 안에서 돌아간다.

### 1.2 추천 기술 구성 [제안]

| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 | TypeScript | 베팅 규칙·사이드팟 같은 엔진 버그를 타입으로 미리 잡음 |
| 빌드 | Vite | 빠르고 설정이 단순 |
| UI | React (DOM + CSS) | Claude Code가 다루기 익숙. 10자리 테이블은 DOM으로 충분하고, 글자가 선명하며 반응형 배치가 쉬움 |
| 게임 상태 | 순수 TS 엔진 + 작은 상태 저장소(Zustand 등) | 엔진이 React에 의존하지 않아야 테스트·셀프플레이에 그대로 쓸 수 있음 |
| AI 실행 | Web Worker | AI 계산 중에도 화면이 멈추지 않음 |
| 저장 | IndexedDB (idb, Dexie 같은 래퍼) | 2.9, 2.10 |
| PWA | vite-plugin-pwa | 매니페스트·서비스워커 자동 생성 |
| 테스트 | Vitest(엔진·AI) + Playwright(화면) | 1.5 |
| 배포 | Vercel / Cloudflare Pages / GitHub Pages 중 하나 | 정적 사이트 무료 배포, HTTPS 기본 제공(PWA는 HTTPS 필수) |

- Canvas(PixiJS 등)는 화려한 애니메이션이 필요해지면 그때 검토. 1차는 DOM + CSS 애니메이션으로 충분하다고 판단.

### 1.3 반응형 레이아웃 규칙

- 기준은 기기 종류가 아니라 **화면 비율**
  - 세로(높이 > 너비, 보통 폰): 세로로 긴 타원 테이블, 조작부는 엄지가 닿는 하단 전체 폭.
  - 가로(PC, 태블릿, 눕힌 폰): 가로로 긴 타원 테이블, 조작부는 하단 오른쪽.
- 좌석 배치는 **함수 하나**로: 인원수(6/8/10) + 화면 방향 → 타원 위 좌표(% 단위). 내 자리는 항상 하단 중앙.
- 크기는 화면에 비례(`clamp()`, 컨테이너 쿼리).
- **기준 화면 = 폭 360px 세로 + 10인 테이블**(가장 빡빡한 경우). 여기서 안 겹치면 나머지는 대부분 해결된다.
- 높이는 `100vh` 대신 `100dvh` (모바일 주소창 때문에 화면 아래가 잘리는 문제 방지).
- 노치·홈 바 영역은 `env(safe-area-inset-*)`로 비움.
- 터치 버튼은 최소 44px 이상.

### 1.4 모바일·PC 입력과 브라우저 함정 체크리스트

- 터치와 마우스를 한 번에 처리: Pointer Events.
- 더블탭 확대 방지: `touch-action: manipulation`.
- 화면을 아래로 당겨서 새로고침되어 게임이 날아가는 것 방지: `overscroll-behavior: none` + 자동 저장(2.9).
- 카드를 길게 누르면 글자 선택·메뉴가 뜨는 것 방지: `user-select: none`, 컨텍스트 메뉴 차단.
- 슬라이더: 기본 `<input type="range">`는 폰에서 손잡이가 작다 → 큰 손잡이로 직접 만들고 −/+ 버튼 추가(2.7).
- [선택] PC 키보드 단축키: 폴드 / 체크·콜 / 올인 / 강조(H) / 일시정지(Space). 올인은 단축키에도 확인 단계.
- 게임 중 화면 꺼짐 방지: Screen Wake Lock API. 지원하지 않는 브라우저에서는 그냥 무시.
- 백그라운드 타이머 문제: 2.8 방식으로 해결.
- 한글 폰트: 웹폰트는 용량이 커서 첫 로딩이 느려짐 → 시스템 폰트 또는 필요한 글자만 담은 서브셋 폰트.
- 알려진 제약 (구현 시 실기기로 확인 필요)
  - iPhone Safari는 일반 화면의 전체화면 기능(Fullscreen API)을 지원하지 않는 것으로 알려져 있다 → 홈 화면에 추가(PWA)하면 주소창 없는 앱 화면으로 실행된다.
  - iOS 웹에서는 화면 방향 고정이 잘 안 된다 → 세로·가로 둘 다 제대로 나오게 설계(1.3이 그 대응).
  - 파일 내보내기(2.9): PC는 다운로드, 폰은 공유 시트(Web Share API)로 "파일에 저장"하는 쪽이 더 자연스러울 수 있음 → 기기별로 확인 후 결정.
- 지원 대상 [제안]: 최신 Chrome(안드로이드·PC), iPhone Safari, 삼성 인터넷, Edge.

### 1.5 Claude Code에서 "폰·PC 둘 다 잘 돌아가는지" 확인하는 방법

Claude Code는 내 폰을 직접 만질 수 없다. 그래서 세 겹으로 확인한다.

1. **자동 화면 점검 (Playwright)**: 기기 에뮬레이션으로 작은 iPhone, 큰 iPhone, 안드로이드 360px, 태블릿, PC 1920px × 6/8/10인 × 세로/가로 조합을 자동 스크린샷 → Claude Code가 이미지를 보고 겹침·잘림 수정. WebKit 엔진으로도 돌려서 Safari 쪽 차이를 어느 정도 잡는다.
2. **엔진·AI는 화면 없이**: Vitest 단위 테스트 + 셀프플레이 시뮬레이터(3.11).
3. **실기기 확인은 직접**: 에뮬레이션은 실제 폰과 완전히 같지 않다(특히 Safari).
   - Claude Code를 내 컴퓨터에서 돌리는 경우: 개발 서버를 같은 와이파이에 열고(`vite --host`) 폰으로 접속.

   - 성능: Lighthouse(성능·PWA 점수), 중급 안드로이드 폰에서 AI 결정 시간 측정(3.10 예산).
- 단계(5장)가 끝날 때마다 **실기기 확인**을 체크리스트에 넣는다.

### 2.2 칩 단위 [확정: BB가 아니라 칩 금액으로 표시]

- 기준 블라인드 1/2를 **×100** 해서 실제 칩으로 표시한다 → 첫 레벨 100/200.
- 시작 스택 = 선택한 BB × 200
  - 200BB → **40,000** / 300BB → **60,000** / 500BB → **100,000**
- 화면 표기는 전부 칩 금액(쉼표 구분). BB 환산은 표시하지 않는다. [제안] 설정에서 켤 수 있는 "BB 환산 보기"는 기본 꺼둠.
- 칩 종류: 100 / 500 / 1,000 / 5,000 / 25,000 / 100,000. 스택·베팅·팟은 **칩 그림 + 숫자**로 표시(2.13).
- [제안] 최소 베팅 단위 = 테이블에서 쓰는 가장 작은 칩. 레벨이 오르면 100칩 컬러업(정리) 후 500 단위로 바꾸는 식으로 실제 토너먼트 느낌을 낼 수 있다. (단, 올인 금액은 끝자리가 맞지 않아도 허용)

### 2.4 카드 분배 [확정: 완전 무작위]

- 매 핸드 52장 새 덱 → **Fisher–Yates 셔플**, 난수는 `crypto.getRandomValues`(암호학적 난수). `Math.random` 금지.
- AI와 나에게 **똑같은 절차로** 분배. 특정 플레이어에게 좋은 패를 주는 보정·조작은 일절 없음.
- 핸드마다 셔플 시드를 기록해서 핸드 재현·디버깅에 쓴다.
- 검증: 셀프플레이로 수십만 핸드를 돌려 좌석별 시작 핸드 분포가 이론값과 맞는지 통계 검사(카이제곱 등)한다.

### 2.5 버튼·블라인드·포지션 표시 [확정]

- **첫 핸드의 버튼 위치는 무작위**로 정한다(셔플과 같은 암호학적 난수). [확정]
- 테이블에는 **딜러 버튼(D)만** 표시하고, 핸드마다 시계 방향으로 이동.
- SB·BB(·앤티)는 **자동으로 걸리고** 해당 자리 앞에 칩으로 보인다.
- **UTG/HJ/CO 같은 포지션 이름은 화면에 표시하지 않는다.** 포지션은 플레이어가 직접 계산. (AI는 내부적으로 계산해서 씀)
- **탈락자가 생겼을 때: 데드 버튼 방식** [확정] (실제 토너먼트 방식, "BB는 매 핸드 정확히 한 칸씩")

  **핵심 원칙**: BB는 매 핸드 시계 방향으로 **다음 생존자에게 정확히 한 칸** 이동한다. 그래서 누구도 BB를 건너뛰거나 연달아 두 번 내지 않는다. 대신 버튼과 SB는 빈자리에 놓일 수 있다.

  **매 핸드 위치 정하는 순서** (직전 핸드 기준)
  1. 새 BB = 직전 BB 자리 다음의 **첫 생존자**
  2. 새 SB 자리 = **직전 BB 자리**
     - 그 사람이 살아 있으면 SB를 낸다.
     - 그 사람이 직전 핸드에서 탈락했으면 **SB 없음(데드 SB)**. 이번 핸드는 BB만 걸린다.
  3. 새 버튼 자리 = **직전 SB 자리**
     - 그 자리가 비어 있으면(탈락자 자리 또는 직전 핸드가 데드 SB였던 빈자리) **버튼이 빈자리에 놓인다(데드 버튼).**

  **데드 버튼일 때 행동 순서**
  - 프리플랍: 평소처럼 BB 왼쪽 첫 생존자부터.
  - 플랍 이후: 버튼 자리 왼쪽의 첫 생존자부터. 마지막 행동자는 빈 버튼 자리 오른쪽의 생존자.
  - 쇼다운 순서, 팟 분할 시 남는 칩도 "버튼 자리 왼쪽 첫 생존자" 기준을 그대로 적용.

  **예시** (7인, 좌석 1~7, 직전 핸드 버튼 3 · SB 4 · BB 5)
  - 아무도 탈락 안 함 → 버튼 4 · SB 5 · BB 6
  - 직전 핸드에서 5번(BB) 탈락 → BB 6 · SB 없음(5번 자리 비어 있음) · 버튼 4
  - 직전 핸드에서 4번(SB) 탈락 → BB 6 · SB 5 · 버튼은 빈 4번 자리
  - 직전 핸드에서 6번 탈락 → BB 7 (6번을 건너뛰고 다음 생존자) · SB 5 · 버튼 4

  **헤즈업으로 바뀔 때 (2명 남음)**
  - 헤즈업에서는 버튼이 SB를 내고 프리플랍에 먼저, 플랍 이후엔 나중에 행동한다.
  - 헤즈업으로 넘어가는 첫 핸드에는 **같은 사람이 BB를 연달아 두 번 내지 않도록** 버튼 위치를 조정한다. 즉 직전 핸드에서 BB가 아니었던 사람이 BB, 다른 사람이 버튼(=SB).
  - 헤즈업에서는 데드 버튼·데드 SB가 생기지 않는다.

  **BB 앤티와의 관계**: 데드 SB인 핸드에도 BB 자리 사람은 BB와 BB 앤티를 그대로 낸다.

  **화면 표시**
  - 탈락자가 생겨도 **좌석을 당겨서 재배치하지 않는다.** 빈 의자로 남겨 둬야 데드 버튼이 어느 자리에 있는지 보인다.
  - D 버튼은 빈자리에도 그대로 표시한다. 데드 SB인 핸드에는 SB 칩이 놓이지 않는다.
  - 포지션 이름은 여전히 표시하지 않는다. 데드 버튼 상황의 포지션 계산도 플레이어가 직접 한다.

  **AI 쪽 처리**: AI는 포지션을 버튼 좌석 번호가 아니라 **실제 행동 순서**(내 뒤에 남은 사람 수, 플랍 이후 마지막 행동자인지)로 계산한다(3.4 상대적 포지션). 그래야 데드 버튼에서도 틀리지 않는다.

  **같은 핸드에서 여러 명이 탈락했을 때 순위**: 그 핸드를 **시작할 때 칩이 더 많았던 사람이 더 높은 순위**. 시작 칩이 같으면 공동 순위. 내가 같이 탈락한 경우도 똑같이 적용한다.

  > 위 내용은 TDA 데드 버튼 규정을 기준으로 정리한 것이다. 구현 전에 최신 TDA 규정 원문과 대조해서 다른 부분이 있으면 규정을 따른다.

### 2.6 엔진이 반드시 지켜야 할 베팅 규칙

- 노리밋. 최소 벳 = BB. 최소 레이즈 = 직전 벳/레이즈의 증가분 이상.
- 레이즈 금액은 "총액(to)" 기준으로 표시. 예: "레이즈 12,000".
- 완전한 레이즈에 못 미치는 올인은 **이미 행동한 플레이어에게 다시 레이즈할 권리를 주지 않는다.**
- 여러 명 올인 시 **사이드팟** 정확히 분리. 팟 분할 시 남는 칩은 버튼 왼쪽에 가장 가까운 승자에게.
- BB 앤티는 BB의 라이브 벳에 포함되지 않는다. [확인 필요] BB 자리 칩이 부족할 때 앤티와 블라인드 중 무엇을 먼저 내는지는 TDA 최신 규정을 확인해서 반영.
- 쇼다운 순서: 리버 마지막 공격자가 먼저, 리버에 베팅이 없었으면 버튼 왼쪽부터. 진 쪽은 머크 가능. 올인 상황이면 전원 공개.
- 이 규칙들은 **UI·AI보다 먼저, 단위 테스트로 고정**한다.

### 2.7 조작 UI [확정: 슬라이더 + 베팅 / 폴드 / 올인]

- **슬라이더**: 최솟값 = 콜(또는 체크) 금액, 최댓값 = 올인. 칩 단위로 스냅.
- **베팅 버튼**: 슬라이더 위치에 따라 이름과 금액이 바뀐다.
  - 슬라이더 최솟값 + 받은 벳 없음 → "체크"
  - 슬라이더 최솟값 + 받은 벳 있음 → "콜 2,000"
  - 그 이상 → "벳 5,000" / "레이즈 12,000"
- **폴드 버튼**, **올인 버튼**.
- [확인 필요] 체크·콜을 베팅 버튼에 합치는 위 방식이 괜찮은지. (따로 버튼을 두는 방식도 가능)
- [제안] 모바일 오조작 방지
  - 체크가 가능한데 폴드를 누르면 확인을 받거나 그냥 체크 처리.
  - 올인은 길게 누르기 또는 한 번 더 확인.
  - 스택이 100,000이고 단위가 100이면 슬라이더 칸이 1,000개라 손가락으로 맞추기 어렵다 → 슬라이더 옆에 **− / + 미세조정 버튼**.
  - (선택) 1/3팟·1/2팟·팟 빠른 버튼. 기본은 슬라이더만.
- 화면 상단 정보: 현재 레벨, 블라인드/앤티, **다음 레벨까지 남은 시간(분:초 카운트다운)** [확정], 다음 레벨 블라인드 미리보기, 남은 인원, 평균 스택, **일시정지 버튼**.
- **"지금 핸드 강조하기" 버튼** [확정]: 별 아이콘 + 글자. 액션 버튼(폴드·베팅·올인) 줄과 떨어진 곳(상단 또는 내 좌석 옆)에 둬서 잘못 누르지 않게. 자세한 동작은 2.12.
- **게임 포기**는 실수로 누르면 안 되니 상단 메뉴(☰) 안에 둔다. 자세한 동작은 2.11.
- 팟 표시: 테이블 중앙에 **칩 더미로 크게**, 메인 팟과 사이드팟 따로 (2.13).

### 2.8 일시정지 [확정]

- 혼자 하는 게임이라 구현이 어렵지 않다.
- 일시정지 버튼 → **레벨 타이머 정지 + AI 진행 정지**. 다시 누르면 남은 시간부터 재개.
- 자동 일시정지: 앱이 백그라운드로 가거나 화면이 꺼질 때(`visibilitychange`).
- 구현 주의: 타이머를 `setInterval` 틱 횟수로 세면 모바일 백그라운드에서 틱이 늦어져 시간이 틀어진다. **"레벨 남은 ms"를 상태로 저장**하고, 진행 중일 때만 실제 시각 차이(timestamp)로 깎는 방식으로 만든다.
- 일시정지 중에는 생각할 시간이 무제한이 되지만, 학습용 게임이라 허용한다.

### 2.9 저장·이어하기 [확정: 자동 저장 + 파일 내보내기/불러오기]

두 가지를 같이 만든다.

1. **자동 저장 (브라우저 안, IndexedDB)**
   - 매 액션·매 핸드 종료 시 저장. 앱을 다시 열면 "이어하기" 버튼.
2. **파일 내보내기 / 불러오기 (`.json`)**
   - 백업용, 그리고 폰 ↔ PC 기기 이동용.

저장 내용: 설정, 현재 레벨과 남은 시간, 좌석·스택·버튼 위치, 탈락 순서, **AI 상태 전부**(성향, 개인차, 틸트 등 기분, 상대 통계), 핸드 기록, **강조한 핸드 목록(2.12)**, 저장 형식 버전 번호.
→ AI의 기억과 기분까지 저장해야 이어 했을 때 같은 사람들과 계속 치는 느낌이 유지된다.

주의:
- 브라우저 데이터를 지우거나 시크릿 모드로 하면 자동 저장은 사라진다. iOS Safari는 홈 화면에 추가하지 않은 사이트의 저장 데이터를 한동안 방문하지 않으면 지울 수 있는 것으로 알려져 있다(정확한 조건은 확인 필요). → **파일 백업 기능이 안전장치.**
- **파일 내보내기는 핸드와 핸드 사이에만** 허용한다. 핸드 도중에 저장하면 파일 안에 아직 공개되지 않은 AI 카드와 남은 덱이 들어가서, 파일을 열어 보면 패가 보이기 때문이다.
- 핸드 도중 앱이 꺼진 경우는 자동 저장으로 그 핸드 상태를 그대로 복원한다(내부 저장소라 쉽게 보이지 않지만 완벽한 보호는 아님).
- 저장 파일에 버전 번호를 넣어서, 게임을 업데이트한 뒤에도 예전 파일을 불러올 수 있게 변환 처리.
- 파일을 직접 고쳐 칩을 늘리는 건 혼자 하는 게임이라 막지 않는다. (원하면 체크섬으로 "수정된 파일" 표시만)

### 2.10 핸드 기록·복기 [확정: 학습 목적]

**모든 핸드를 자동 기록**한다. 엔진 단계부터 기록기를 넣어 두면 디버깅에도 쓸 수 있다.

- 기록 항목: 핸드 번호, 레벨, 블라인드/앤티, 버튼 위치, 좌석별 시작 스택, 내 카드, 모든 AI 카드, 보드, 모든 액션(순서·금액), 팟·사이드팟 결과, 쇼다운, 종료 스택, 셔플 시드.
- **AI 판단 메모** (학습용): AI가 액션할 때마다 그 AI가 본 에퀴티 추정, 팟오즈, 행동 확률(예: "콜 60% / 폴드 40% → 콜 뽑힘"), 성향.
- **내 결정 비교**: 내가 결정한 시점마다 "AI 기본 전략이었다면" 행동 확률과 에퀴티 추정을 같이 기록한다. 근사치라 정답이 아니고, 화면 표기도 "AI 기준"으로.
- [확인 필요] **AI 카드 공개 시점**
  - [제안] 게임 중 복기 화면에서는 쇼다운에서 실제로 보인 카드만 보여준다.
  - 토너먼트가 끝나면 **AI 카드 전체 공개**: 그때 블러프였는지 확인할 수 있다. AI별 **레벨과 성향도 이때 공개**(3.6).
  - 게임 중에 다 보여주면 AI 성향을 미리 알아버려서 실전 연습이 안 된다.
- 복기 화면
  - **핸드 리플레이어**: 한 액션씩 앞/뒤로 넘기기
  - 필터: **강조한 핸드만(2.12)** / 내가 참여한 핸드 / 큰 팟 / 올인 / 내가 진 핸드
  - 핸드마다 메모 달기
  - 내 통계: VPIP, PFR, 3벳%, C벳%, 포지션별 성적 (포지션은 기록상 계산해서 복기에서만 표시)
  - 지난 토너먼트 목록 보관
  - **"이 AI 행동 이상함" 신고 버튼**: AI 액션마다 누를 수 있다. 신고 목록 내보내기 (3.14 ⑥)
- 내보내기: JSON(전체 데이터) + 사람이 읽기 쉬운 텍스트 핸드 히스토리. 다른 포커 분석 프로그램에서 열리게 형식을 비슷하게 맞출 수는 있지만 호환은 보장 못 한다 → 2차 과제.
- 용량: 핸드당 수 KB 정도(AI 메모 포함 시 더 큼)로 예상한다. localStorage는 보통 5MB 안팎 제한이라 부족할 수 있으니 **IndexedDB**에 저장.

### 2.11 게임 포기 [확정]

- 위치: 상단 메뉴(☰) → "게임 포기". 액션 버튼 근처에 두지 않는다.
- 누르면 확인 창: "포기하면 이 토너먼트는 이어 할 수 없어요. 기록은 복기용으로 남아요." → [포기] / [취소]
- 확인 창이 떠 있는 동안은 자동으로 일시정지.
- 포기했을 때 처리
  - 핸드 도중이면 그 핸드는 **폴드로 처리**하고, 그 시점까지 핸드 기록에 남긴다.
  - 결과 기록: "포기" 표시 + 포기 시점의 순위(**남은 인원 중 최하위**로 처리) [확정], 레벨, 진행 시간, 핸드 수.
  - **남은 AI끼리 나머지 토너먼트를 진행하지 않고 그 자리에서 끝낸다.** [확정]
  - 자동 저장의 "이어하기"는 삭제한다. **핸드 기록·강조 목록은 지난 토너먼트 목록에 그대로 남긴다.**
  - 토너먼트가 끝난 것으로 보고 바로 결과 화면 → 복기로 이어진다. AI 카드 전체 공개 규칙(2.10)도 똑같이 적용.
- 칩을 전부 잃어서 탈락한 경우도 같은 결과 화면 → 복기 흐름으로 간다.

### 2.12 "지금 핸드 강조하기" [확정]

토너먼트가 끝난 뒤 다시 보고 싶은 순간을 게임 중에 표시해 두는 버튼.

- **한 번 누르면 바로 표시**되고 게임은 멈추지 않는다. 버튼이 "★ 강조됨"으로 바뀐다. 다시 누르면 취소.
- 무엇이 저장되나
  - 어느 핸드인지 (핸드 번호)
  - **누른 순간**: 스트리트와 몇 번째 액션이었는지 → 복기할 때 그 핸드를 처음부터가 아니라 **그 순간부터** 열어 준다.
- 누르는 시점별 규칙
  - 핸드 진행 중 → 지금 핸드
  - 핸드가 끝나고 결과(쇼다운·팟 정산)가 보이는 동안 → 방금 끝난 핸드. 결과 순간으로 저장.
  - 내가 이미 폴드한 뒤에도 그 핸드가 끝날 때까지 누를 수 있다. (다른 사람끼리 싸우는 장면을 보고 싶을 때)
- 메모는 게임 중에 쓰지 않는다. 입력하느라 흐름이 끊기기 때문이다. 메모는 복기 화면에서 단다.
  - [선택] 메모를 꼭 남기고 싶으면, 길게 누를 때 한 줄 메모 창을 띄우고 그동안 자동 일시정지.
- 게임 중에는 강조해도 **AI 카드가 공개되지 않는다.** 공개는 토너먼트 종료 후(2.10 규칙).
- 토너먼트 종료(우승·탈락·포기) 화면에 **"강조한 핸드 N개 복기하기"** 버튼을 크게 둔다. 누르면 강조한 핸드만 순서대로, 각자 강조한 순간부터 열린다.
- 강조 목록은 자동 저장과 내보내기 파일에 포함한다(2.9).
- [선택] PC에서는 단축키(예: `H`)로도 강조.

### 2.13 칩·팟 표시 [확정: 팟에 칩이 보이는 게 가장 중요]

**칩 색 (초기값, `src/data/chips.json`에서 변경 가능)**

| 칩 | 색 |
|---|---|
| 100 | 흰색 |
| 500 | 보라 |
| 1,000 | 노랑 |
| 5,000 | 빨강 |
| 25,000 | 초록 |
| 100,000 | 검정 (테두리 금색) |

**팟 (테이블 중앙, 화면에서 가장 눈에 띄게)**
- 금액을 **큰 단위 칩부터 나눠서**(예: 37,500 → 25,000×1, 5,000×2, 1,000×2, 500×1) 칩 더미 그림으로 쌓는다.
- 더미 위나 아래에 **정확한 금액 숫자**를 항상 같이 표시한다. 칩 그림은 느낌, 숫자는 정확함.
- 칩이 많아지면 한 줄에 최대 8~10개까지 쌓고 옆으로 줄을 늘린다. 줄 수도 상한(예: 6줄)을 두고 넘으면 더 큰 칩으로 보여준다 → 화면 성능과 가독성 유지.
- 사이드팟은 메인 팟 옆에 **따로 칩 더미**로, "사이드 1" 같은 작은 이름표와 금액.

**베팅 칩의 움직임 (실제 테이블처럼)**
- 각자 베팅하면 그 사람 자리 앞(테이블 쪽)에 칩 더미가 놓인다. 블라인드·앤티도 칩으로 보인다.
- 스트리트가 끝나면 앞에 놓인 칩들이 **중앙 팟으로 미끄러져 모인다.**
- 핸드가 끝나면 팟 칩이 **이긴 사람 자리로 미끄러져 간다.** 팟을 나누면 나눠서 각자에게.
- 애니메이션 속도는 AI 속도 설정을 따른다. 빠름이면 짧게.

**스택**
- 각 자리에 남은 칩을 작은 칩 더미 + 숫자로.
- 올인한 사람은 스택 자리에 "올인" 표시.

**가독성**
- 칩 색만으로 구분하지 않는다. 숫자가 항상 같이 있어서 색 구분이 어려워도 문제없다.
- 360px 폭 세로 10인 화면에서도 팟 칩 더미와 숫자가 가장 먼저 눈에 들어오게 크기를 잡는다(1.5 스크린샷 점검 대상).

### 2.14 AI 닉네임 [확정]

홀덤펍 닉네임처럼 재미있는 이름을 AI에게 붙여서, 상대를 쉽게 기억하고 "아까 그 리버요정이 또 블러프하네" 하며 칠 수 있게 한다.

**규칙**
- 토너먼트 시작 때 이름 목록에서 **무작위로, 겹치지 않게** 뽑는다.
- **이름은 성향·레벨과 무관하게 무작위.** 이름으로 스타일이 드러나면 게임 중 레벨·성향을 숨기는 규칙(3.6)이 깨지기 때문이다. 그래서 "올인각"이 사실은 바위 같은 니트일 수도 있다. 이름 믿지 말고 직접 파악하는 게 재미 포인트.
- 한 토너먼트 동안 이름은 고정. 자동 저장·파일 내보내기·핸드 기록·복기에 이름이 그대로 남는다.
- 토너먼트가 끝나면 결과 화면에서 "리버요정 — 매니악 Lv3"처럼 이름과 정체를 같이 공개.
- 자리 표시 공간 때문에 이름은 **최대 5글자**.
- [제안] 이름마다 무작위 색 테두리를 줘서 이름과 함께 색으로도 기억하기 쉽게.

## 3. AI 설계 (핵심)

### 3.1 목표와 정직한 한계

목표 네 가지:
1. **빠르게**: 계산은 폰에서도 수십 ms 안에 끝낸다.
2. **정확하게**: 확률·팟오즈·GTO 공식에 근거한 판단.
3. **때로는 사람처럼**: 고민 시간, 실수, 감정(틸트), 버릇.
4. **AI마다 다른 스타일**: 같은 엔진, 다른 성격 파라미터.

한계:
- PioSolver 같은 실제 솔버는 한 상황을 푸는 데도 PC에서 수 분 이상 걸린다. 폰 브라우저에서 매 핸드 실시간으로 푸는 건 불가능하다.
- 그래서 이 AI는 **"솔버 원리를 흉내 낸 빠른 근사 봇"**이다. 프리플랍과 숏스택 푸시/폴드는 꽤 정확하게 만들 수 있지만, 깊은 스택 포스트플랍은 근사다. 실력 있는 사람은 약점을 찾아낼 수 있다.
- 이 문서의 숫자(오픈 비율, 성향별 VPIP 등)는 전부 **조정용 초기값**이고 검증된 정답이 아니다. 셀프플레이로 튜닝해야 한다.
- 화면에 "솔버 정답"이라고 표시하지 말 것. 필요하면 "AI 기준" 정도로 표기.

### 3.2 공정성 원칙 (구조로 강제)

- 엔진은 각 플레이어에게 **`PlayerView`**(본인 카드 + 공개 정보만 담긴 객체)를 만들어 넘긴다.
- AI 함수는 `PlayerView`만 받는다. 덱이나 다른 사람 카드에 **타입상 접근할 수 없게** 설계한다.
- AI의 상대 기억도 **공개된 정보**(액션, 쇼다운에서 보인 카드)만으로 쌓는다.

```ts
type PlayerView = {
  handId: string;
  mySeat: number;
  holeCards: [Card, Card];          // 본인 카드만
  board: Card[];
  street: 'preflop' | 'flop' | 'turn' | 'river';
  buttonSeat: number;
  seats: { seat: number; stack: number; committed: number;
           status: 'active' | 'folded' | 'allin' | 'out' }[];
  pots: { amount: number; eligibleSeats: number[] }[];
  actionLog: PublicAction[];        // 이번 핸드의 공개 액션
  legal: { canCheck: boolean; callAmount: number;
           minRaiseTo: number; maxRaiseTo: number };
  level: { sb: number; bb: number; ante: number };
  playersLeft: number;
};

type Decision = { type: 'fold' | 'check' | 'call' | 'raise'; to?: number; thinkMs: number };
```

### 3.3 전체 구조: 3층 + 1

```
[1층] 기본 전략(정확함)   ─ 프리플랍 표 / 포스트플랍 레인지·확률 계산 / GTO 공식
        ↓  행동별 확률 분포 (예: 폴드 20%, 콜 50%, 레이즈 30%)
[2층] 스타일(개성)        ─ 성격 파라미터로 확률 분포를 기울임
        ↓
[3층] 사람다움            ─ 온도(실수), 틸트, 버릇, 베팅 금액 반올림, 고민 시간
        ↓
[+1] 단순 기억 반응       ─ 쇼다운에서 본 장면에 잠깐 반응 (통계 기반 착취는 하지 않음, 3.8)
        ↓
   확률대로 뽑기(샘플링) → 최종 행동 + 고민 시간
```

핵심 아이디어: **AI는 "정답 한 개"가 아니라 "행동별 확률"을 낸다.** 그 확률을 성격·감정·실력으로 조금씩 비튼 다음 주사위를 굴린다. 그래서 같은 상황에서도 매번 똑같이 행동하지 않는다(솔버의 혼합 전략과 같은 원리). 성향 차이는 확률을 비트는 방향에서 나온다.

**무작위는 "말이 되는 선택지들 사이에서만"이다.** 주사위를 굴리기 전에 3.12의 안전장치가 말도 안 되는 행동을 후보에서 지운다. 예를 들어 리버에서 미들페어로 반 팟 벳을 받았을 때 "콜 60% / 폴드 40%"처럼, 실력 있는 사람도 고민할 만한 선택지끼리만 섞는다. 프리플랍 AA 폴드 같은 행동이 확률로 튀어나오는 일은 없게 한다.

```ts
function decide(view: PlayerView, persona: Persona, mem: AIMemory): Decision {
  const ctx = buildContext(view);                 // 포지션, 유효스택(BB), SPR, 팟오즈, 보드 텍스처
  const ranges = mem.rangeTracker.update(view);   // 상대 레인지 추정 갱신
  const base = view.street === 'preflop'
    ? preflopPolicy(ctx, persona)                 // 표 조회 (~0ms)
    : postflopPolicy(ctx, ranges);                // 레인지 백분위 + GTO 공식
  const evDist = evPolicy(ctx, ranges);                  // 평균적인 상대 기준 기대값 (특정 상대 착취 아님)
  let dist = blend(base, evDist, persona.evWeight);
  dist = applyHabits(dist, ctx, persona, mem);           // 3.7 ①: 성향별 습관 — 사람다움의 핵심
  dist = applyStyle(dist, persona, mem.mood, mem.recall);// 성격 + 감정 + 단순 기억 반응
  dist = applyTemperature(dist, persona.skillTemp);      // 실력이 낮을수록 흐트러짐
  dist = applyGuards(dist, ctx, persona);                // 3.12: 금지 행동 제거 + 너무 작은 확률 잘라내기
  const action = sample(dist);
  return { ...humanizeSize(action, ctx, persona), thinkMs: thinkTime(ctx, persona) };
}
```

### 3.4 프리플랍 (빠르고 꽤 정확하게)

**① 169개 시작 핸드 순위표 (미리 계산)**
- AA, AKs, AKo … 169종을 오프라인 스크립트로 강도 순위를 매겨 JSON으로 넣는다. 기준은 랜덤 핸드 상대 에퀴티 또는 상위 레인지 상대 에퀴티.
- 각 핸드의 콤보 수(페어 6, 수딧 4, 오프 12)를 반영해서 **상위 몇 %인지(백분위)**로 바꿔 둔다.

**② 상황별 기준선 (표)**
- 상황 키: `(행동 유형, 상대적 포지션, 유효 스택 구간)`
  - 행동 유형: 첫 진입 오픈 / 오픈에 대응(3벳·콜·폴드) / 3벳에 대응 / 4벳 이상 / 림프팟
  - 상대적 포지션: "내 뒤에 남은 사람 수" 기준으로 계산하면 6·8·10인 테이블에 같은 로직을 쓸 수 있다.
  - 스택 구간: 100BB 이상 / 40–100 / 20–40 / 12–20 / 12 미만
- **첫 진입 오픈 비율 초기값** (전부 조정용 값, 검증된 정답 아님). 프로토타입에서 SB는 림프 없이 레이즈 또는 폴드만.

| 인원 | 포지션별 오픈 % |
|---|---|
| 6인 | UTG 15 · HJ 20 · CO 27 · BTN 45 · SB 40 |
| 8인 | UTG 11 · UTG+1 13 · LJ 16 · HJ 20 · CO 27 · BTN 45 · SB 40 |
| 10인 | UTG 9 · UTG+1 10 · UTG+2 11 · MP 13 · LJ 15 · HJ 18 · CO 25 · BTN 43 · SB 40 |

- **오픈에 대응할 때 초기 규칙** (상대 오픈 레인지 폭을 o%라고 할 때)
  - 3벳: 상위 약 0.25 × o% (밸류) + 깊은 스택에서는 그 절반 정도의 블러프(A2s–A5s, 수딧 커넥터)
  - 콜: 3벳 범위 다음 약 0.5 × o%. 인포지션이면 조금 넓게, BB는 팟오즈 덕분에 약 1.5배 넓게, SB는 3벳 아니면 폴드 위주
  - 나머지 폴드
- **3벳을 받았을 때**: 4벳은 최상위(QQ+, AK 수준) + 소수 블러프(A5s 등), 콜은 그다음 일부(JJ–TT, AQs 수준), 나머지 폴드. 4벳 이후에는 남은 스택이 팟에 비해 작으면 올인 또는 폴드.
- 오픈 크기 초기값: 2.2–2.5BB(깊을수록 크게), 3벳은 인포지션 약 3배·아웃오브포지션 약 4배, 4벳은 약 2.3배.
- 상업용 솔버 차트(GTO Wizard 등)를 그대로 복사하지 말 것(약관·저작권 문제). 직접 생성하거나 공식으로 만든다.

**③ 경계를 부드럽게 (혼합 전략이 자연스럽게 나옴)**

```
P(레이즈 | 핸드) = sigmoid( (기준선 + 성격.루즈함 − 핸드백분위) / 폭 )
```

- 기준선 근처 핸드는 50:50처럼 섞여서 나온다 → 솔버처럼 보이고 패턴이 덜 읽힌다.
- 성향별로는 `루즈함`(기준선 이동)과 `폭`(얼마나 들쑥날쑥한지)만 바꾸면 된다.
- 3벳 레인지는 깊은 스택에서는 **양극화**(강한 패 + 일부 블러프용 수딧 A·수딧 커넥터), 얕은 스택에서는 **선형**(강한 순서대로).

**④ 숏스택 푸시/폴드 (여기는 실제로 정확하게 가능)**
- 유효 스택 약 12–15BB 이하면 "올인 아니면 폴드"로 전환.
- 내시 균형 푸시/콜 레인지를 **오프라인에서 직접 계산**(헤즈업은 fictitious play 등으로 계산 가능)해서 JSON으로 넣는다. 멀티웨이는 근사.
- 1차는 칩 기준(chipEV). ICM은 3.9 참고.
- **프로토타입 근사**: 정확한 내시 표 대신 "유효 스택이 작을수록, 내 뒤에 남은 사람이 적을수록 올인 범위가 넓어지는" 단조 함수로 시작한다. 올인을 받아 콜하는 범위는 올인 범위보다 좁게, 팟오즈로 조정. 대략적인 감 잡기용 앵커(기억에 의존한 대략값, **검증 안 됨**): 10BB에서 SB 대 BB 올인 약 50–60%, BTN 약 35–40%. 다음 단계에서 직접 계산한 내시 표로 교체한다.

### 3.5 포스트플랍 (근사지만 원리대로)

**① 상대 레인지 추적**
- 각 AI는 상대마다 1,326개 콤보에 가중치를 매겨 둔다.
- 상대가 액션할 때마다 `가중치 *= P(그 액션 | 그 콤보)`로 베이즈 갱신. P는 "평균적인 플레이어 모델"(= 1층 기본 전략에 상대 추정 성향을 입힌 것)로 계산.
- 내 카드·보드와 겹치는 콤보는 제거.

**② 에퀴티 계산 (빠른 핸드 평가기 필수)**
- 7장 핸드 평가기는 성능 핵심. 비트마스크 방식 직접 구현, 또는 공개 평가기 JS 포팅 후보(예: HenryRLee/PokerHandEvaluator 계열)를 검토. **라이선스·속도는 Claude Code가 확인.**
- 스트리트별 방식
  - 리버: 남은 카드가 없으니 상대 레인지 콤보와 **정확히 비교**(빠르고 정확).
  - 턴: 리버 카드 44–46장 × 레인지 **전수 계산** 가능.
  - 플랍: **몬테카를로** 샘플 1,000–3,000회.
  - 멀티웨이: 모든 상대 레인지를 함께 샘플링.
- 결과 캐싱: `(내 핸드, 보드, 레인지 해시)` → 에퀴티.

**③ 한 번 계산으로 모든 베팅 크기 평가 (속도 핵심)**
- 상대 레인지를 강도 순으로 10개 묶음(버킷)으로 나누고, 버킷별 내 에퀴티를 한 번만 계산한다.
- "상대가 상위 q%로만 콜한다"를 가정하면 콜 레인지 상대 에퀴티는 버킷 평균만으로 바로 나온다 → 33% / 50% / 75% / 100% / 150% / 올인을 추가 계산 없이 비교할 수 있다.

**④ 기본 전략: 레인지 백분위 + GTO 공식 (균형형)**

AI는 상대가 보는 **자기 레인지**도 추적하고, 지금 핸드가 그 레인지에서 위에서 몇 %인지 본다.

- **베팅할 때 (공격자)**
  - 밸류 구간: 레인지 상위 v% (v는 레인지 우위와 보드 텍스처로 결정)
  - 블러프 비율: 리버에서 팟 P에 b를 베팅하면, 베팅 레인지 중 블러프 비율 = **b / (P + 2b)**
    - 예: 팟 크기 베팅 → 베팅의 1/3이 블러프, 반 팟 → 1/4
  - 블러프 후보: 쇼다운 가치가 없고, 상대 강한 패를 막는 카드(블로커)를 가진 핸드 우선
  - 플랍·턴은 에퀴티가 있는 드로우로 세미블러프 비율을 더 높게
- **베팅을 받았을 때 (수비자)**
  - 최소 수비 빈도(MDF) = **P / (P + b)** → 레인지 상위 그만큼은 콜·레이즈, 나머지 폴드
  - 레이즈는 최상위 + 일부 드로우
- **베팅 크기 선택 (텍스처 기반)**
  - 드라이 보드(예: K72 레인보우) → 작게(25–33%), 자주
  - 웻 보드(예: J♥T♥8♣) → 크게(66–100%+), 덜 자주
  - 스택 대비 팟(SPR)이 작으면 올인 후보 포함

이 공식들(블러프 비율, MDF)은 실제 게임이론에서 나오는 "상대를 무차별하게 만드는" 조건이라, 계산은 가볍지만 균형 잡힌 행동이 나온다.

**⑤ 기대값(EV) 계산 (평균적인 상대 기준)**

```
EV(폴드) = 0
EV(콜)   = 실현에퀴티 × (팟 + 콜금액) − 콜금액
           실현에퀴티 = 에퀴티 × 실현계수 (인포지션 > 아웃오브포지션, 리버 = 1)
EV(벳 b) = f × 팟 + (1 − f) × [ 콜레인지 상대 에퀴티 × (팟 + 2b) − b ]
           f = 상대가 폴드할 확률 (특정 상대가 아니라 "평균적인 플레이어" 모델로 추정)
```

- 각 EV를 팟 크기로 나눠 정규화한 뒤, 3.7의 온도 공식으로 확률로 바꾼다.
- 최종 = `기본 전략 × (1 − evWeight) + EV 전략 × evWeight`
  - 솔버는 evWeight 낮음(균형 유지). 다른 성향은 중간 정도. 사람은 균형보다 "이게 이득 같다"는 감으로 치기 때문.
- 특정 상대(성진 님 포함)의 통계를 보고 파고드는 착취는 **하지 않는다**(3.8).

### 3.6 스타일(성격) 파라미터

모든 AI는 **같은 엔진**을 쓰고 파라미터만 다르다. 같은 성향끼리도 자리마다 ±10% 정도 무작위로 흔들어서 개인차를 준다.

| 파라미터 | 의미 |
|---|---|
| `looseness` | 프리플랍 참여 기준선 이동 (VPIP) |
| `aggression` | 콜 대신 벳·레이즈 선호도 |
| `bluffMult` | 블러프 빈도 배수 (1.0 = 균형) |
| `cbetFreq` | 컨티뉴에이션 벳 경향 |
| `stickiness` | 한번 들어가면 끝까지 콜하는 정도 |
| `foldToAggro` | 큰 벳·3벳에 접는 경향 |
| `sizing` | 베팅 크기 성향 (작게 자주 / 표준 / 양극화·오버벳) |
| `skillTemp` | 실력 온도 (낮을수록 정확) |
| `evWeight` | 균형 전략 대신 "이득 같은 쪽"을 따르는 정도 |
| `habits` | 성향별 습관 목록과 지키는 비율 (3.7 ①) |
| `tiltProne` | 큰 팟을 잃은 뒤 흔들리는 정도 |
| `moodRange` | 기분(자신감·조급함·지루함)에 흔들리는 폭 |
| `recall` | 쇼다운에서 본 장면에 반응하는 정도와 지속 핸드 수 (3.8) |
| `tells` | 시간·사이즈 버릇 유무 |
| `showdownStyle` | 이겼을 때 패 보여주기, 블러프 자랑하기 등 |

**성향 예시 (목표 통계는 셀프플레이 튜닝용 초기값, 검증된 수치 아님)**

| 성향 (펍 별명 예) | 특징 | 목표 VPIP / PFR (6인 기준 대략) |
|---|---|---|
| GTO봇 "솔버" | 균형형, 습관 없음(혼합 전략), 감정 없음, 온도 매우 낮음 | 22–25 / 18–21 |
| TAG "레귤러" | 타이트·공격적, 정석 습관이 뚜렷함, 감정 적음 | 20–24 / 17–20 |
| LAG "공격수" | 넓게 들어와서 많이 압박 | 28–35 / 24–30 |
| 콜링스테이션 "끝까지 간다" | 잘 안 접고, 레이즈 적음 | 40–55 / 5–10 |
| 니트 "바위" | 아주 타이트, 큰 벳에 잘 접음 | 10–14 / 8–12 |
| 매니악 "올인맨" | 과도한 블러프·오버벳 | 55–70 / 40–55 |
| 초보 "입문자" | 림프 많음, 사이즈 버릇, 실수 많음 | 35–45 / 8–12 |

**실력 레벨 (Lv1~10)과 난이도** [확정]

**성향(스타일)과 실력(레벨)을 분리한다.** 성향은 "어떻게 치는가"(타이트·루즈, 공격·수동), 레벨은 "얼마나 잘 치는가"다. 같은 공격수라도 Lv4 공격수와 Lv9 공격수는 완전히 다르다.

레벨이 정하는 것 (초기값, 셀프플레이로 튜닝)

| 항목 | Lv1–3 (피쉬) | Lv4–6 (중간) | Lv7–8 (강함) | Lv9–10 (최상) |
|---|---|---|---|---|
| 실수 온도 τ (3.7 ②) | 높음 | 중간 | 낮음 | 매우 낮음 |
| 나쁜 습관(릭) | 3–4개, 강하게 | 1–2개, 약하게 | 0–1개, 아주 약하게 | 없음 |
| 좋은 습관의 정확도 | 낮음 (정석과 거리 있음) | 보통 | 높음 | 정석 그대로 |
| 생각하는 수준 | **내 패만 봄** (상대 레인지 무시) | 상대 레인지를 대충 봄 | 레인지로 생각 | 레인지 + 블로커·MDF·블러프 비율까지 |
| 숏스택 올인 정확도 | 감으로 | 대략 | 표에 가까움 | 표대로 |
| 베팅 크기 실수 | 자주 (민레이즈, 이상한 크기) | 가끔 | 거의 없음 | 없음 |
| 틸트·감정 흔들림 | 큼 | 중간 | 작음 | 아주 작음 (Lv10 솔버는 0) |
| 읽히는 버릇(텔) | 있음 | 일부 | 없음 | 없음 |

- "내 패만 봄 → 레인지로 생각"으로 나누는 게 사람답다. 실제 초보는 상대가 뭘 들었을지보다 자기 패만 보고 치기 때문이다.
- 높은 레벨도 좋은 습관과 약한 감정은 남겨서 **사람 느낌은 유지**한다. 습관·감정이 전혀 없는 건 Lv10 솔버뿐이다.

성향별로 가질 수 있는 레벨 범위

| 성향 | 레벨 범위 | 비고 |
|---|---|---|
| 초보 "입문자" | Lv1–3 | 피쉬 |
| 콜링스테이션 "끝까지 간다" | Lv1–4 | 피쉬 |
| 매니악 "올인맨" | Lv2–5 | 피쉬 |
| 니트 "바위" | Lv3–7 | |
| 공격수 (LAG) | Lv4–10 | |
| 레귤러 (TAG) | Lv4–10 | |
| 솔버 (GTO봇) | Lv9–10 | |

- **피쉬** = Lv1–4이거나 피쉬 성향(초보·콜링스테이션·매니악)인 AI.

난이도별 설정

| 난이도 | 레벨 범위 | 피쉬 수 | 느낌 |
|---|---|---|---|
| 보통 | Lv3–7 | 최대 약 30% (10인 기준 2~3명) | 펍 평균. 노릴 만한 사람이 테이블에 있음 |
| 어려움 | Lv5–8 | 최대 1명 | 대부분 정석. 실수가 드묾 |
| 매우 어려움 | Lv7–10 | 0명 | 나쁜 습관이 거의 없음. 솔버 1~2명 포함 가능 |

**레벨을 고르게 배정하는 방법 (균일 분포)**
1. 난이도의 레벨 범위를 AI 수만큼 **고르게 나눠서** 레벨을 정한다. 예: 어려움(Lv5–8)에 AI 9명 → Lv5, 5, 6, 6, 6, 7, 7, 8, 8처럼 범위 전체에 고르게. 한쪽으로 몰리지 않게.
2. 각 레벨에 맞는 성향을 고른다. 피쉬 수 상한을 지키고, 같은 성향이 너무 겹치지 않게 다양하게.
3. 좌석 배치는 무작위. 같은 사람끼리 개인차(±10%)는 그대로 준다.

**레벨 공개**: 게임 중에는 AI의 레벨과 성향을 표시하지 않는다(실전처럼 직접 파악). 토너먼트가 끝나면 결과·복기 화면에서 AI 카드와 함께 공개한다.

**정직한 한계**: 레벨은 **현재 AI 버전 안에서의 상대적인 실력**이다. v1의 Lv10은 실제 솔버만큼 강하지 않다. v2~v4로 AI가 좋아질수록 높은 레벨이 실제로 강해진다.

### 3.7 사람다움 — 착취 없이 갈 수 있는 상한선 [확정: 이 방향으로 최대한]

**상한선의 정의**: 특정 상대를 분석해서 파고드는 것(착취)은 하지 않는다. 그 대신 **"규칙으로 표현할 수 있는 사람의 습관·실수·감정·버릇·기억"은 전부 넣는다.** 이게 이 프로젝트에서 현실적으로 갈 수 있는 사람다움의 최대치다.

**그 위로는 못 가는 것 (정직한 한계)**
- 성진 님 플레이를 읽고 맞춤 대응하기 → 착취라서 제외
- 실제 사람들의 플레이 데이터로 배운 "진짜 사람 분포" → 그런 데이터가 없음. 규칙 + 성진 님의 체감으로 맞춘다
- 말·표정 같은 라이브 텔, 여러 판에 걸친 장기 학습

**① 습관 (사람다움의 핵심)**

중요한 관찰: **확률을 세밀하게 섞는 건 솔버의 특징이지 사람의 특징이 아니다.** 사람은 "나는 드라이 보드면 항상 작게 C벳한다" 같은 **단순한 규칙**으로 친다. 그래서 솔버를 뺀 성향은 혼합 전략 대신 습관을 우선한다.

- 습관 = `조건 → 행동`, 그리고 지키는 비율(예: 85%). 나머지 15%는 1층 기본 전략을 따른다.
- 습관끼리는 일관돼야 한다. 같은 사람이 같은 상황에서 매번 다르게 하면 오히려 로봇 같다.
- 성향별 습관 예시 (초기값, 튜닝 대상)

| 성향 | 습관 예 |
|---|---|
| 레귤러 | 헤즈업 드라이 보드는 거의 항상 1/3팟 C벳 / 3벳은 강한 패 + A5s 류만 / 리버 큰 벳에는 강한 패 아니면 잘 접음 |
| 공격수 | 버튼·컷오프에서 넓게 오픈 / 상대가 체크하면 자주 벳 / 드로우는 거의 항상 세미블러프 |
| 콜링스테이션 | 페어 이상이면 리버까지 콜 / 레이즈는 강한 패일 때만 / 블러프 거의 안 함 |
| 니트 | 프리미엄 패 아니면 3벳에 폴드 / 세트 이상에서만 큰 팟 / 블러프 거의 안 함 |
| 매니악 | 자주 오버벳 / 블러프가 들키면 다음 핸드도 블러프 / 스택 압박을 즐김 |
| 초보 | 아무 A나 림프 / 드로우 쫓아가기 / 강한 패는 슬로플레이 / 벳 크기 = 패 강도 |

**② 체계적 실수 (방향이 있는 실수)**

```
P(행동) ∝ exp( 정규화EV(행동) / τ )
```

- 온도 τ는 성향별 실력 차를 만든다. 다만 **무작위 실수만으로는 사람처럼 안 느껴진다.** 사람은 "일정한 방향으로" 틀린다.
- 사람이 실제로 자주 하는 실수를 성향에 맞게 배정한다.
  - 탑페어 과대평가, 오버카드 무서워하기, 오즈 무시하고 드로우 쫓기
  - 몬스터 패 슬로플레이 과다, 블러프 한 번 콜당하면 그 뒤 포기
  - 방금 진 패를 다음에 다르게 치기(결과에 휘둘리기)
  - 민레이즈, 쓸데없이 화려한 플레이(공격수·매니악)
- 3.12 안전장치 안에서만 일어난다. "사람이 할 법한 실수"까지만이다.

**③ 감정·상태 (mood)**
- **틸트**: 큰 팟을 지거나 배드빗(올인 시 에퀴티 70% 이상이었는데 짐)을 당하면 증가 → 몇 핸드 동안 루즈·공격적. 서서히 회복.
- **자신감**: 연속으로 이기면 조금 더 공격적.
- **지루함**: 오랫동안 패가 안 들어와 계속 폴드하면, 애매한 패로 들어오고 싶어짐(초보·공격수 쪽에서 강하게).
- **조급함·두려움**: 스택이 줄어들수록 조급해지거나(매니악), 반대로 몸을 사림(니트).
- **칩리더 심리**: 칩리더는 짧은 스택을 압박.
- 성향마다 흔들리는 폭(`moodRange`)이 다르다. 솔버는 0.

**④ 토너먼트 흐름에 따른 기어 변화**
- 초반(스택 깊음): 초보·콜링스테이션은 많이 들어오고, 레귤러는 차분.
- 블라인드가 오를 때: 짧은 스택부터 급해진다. 레벨 오르기 직전·직후에 플레이가 바뀌는 사람도 있다.
- 후반(푸시/폴드 구간): 다들 단순해지되, 성향별로 올인 범위가 다르다.

**⑤ 고민 시간 (계산 시간과 분리)**
- 실제 계산은 수십 ms. 화면에 보이는 "고민"은 연출로 따로 넣는다.
- `고민시간 = 기본값 + 결정난이도 × 계수 + 무작위`
  - 결정난이도: 가장 좋은 두 행동의 EV 차이가 작을수록, 팟이 클수록 높음
  - 프리플랍 쓰레기 패 폴드는 빠르게, 큰 리버 결정은 길게
- 설정의 AI 속도(빠름/보통/리얼)로 전체 배율 조정.

- 고민 시간 패턴도 사람답게: 드로우로 바로 콜(스냅콜), 오래 고민하다 폴드, 쉬운 결정은 빠르게.

**⑥ 버릇(텔) [확정: 사람다움 요소로 포함]**
- 일부 AI만 갖는 읽을 수 있는 버릇. 예: 초보는 강한 패일 때 오래 고민하다 작게 벳, 큰 벳 = 진짜 강함.
- 펍에서 사람 읽는 재미를 준다. 솔버·레귤러에는 넣지 않는다.

**⑦ 베팅 금액 습관**
- 사람은 7,340 같은 금액을 내지 않는다 → 칩 단위로 반올림(1,000 / 500 단위 등).
- 레귤러는 크기가 일정, 초보는 민레이즈·이상한 사이즈를 가끔 사용, 드로우일 때 작게 찔러 보기(블로킹 벳).

**⑧ 쇼다운 행동 (연출)**
- 레귤러·니트는 진 패를 조용히 머크.
- 매니악은 가끔 블러프를 일부러 보여줌. 초보는 이기면 다 보여줌.

**⑨ 사람다움 평가**
- 토너먼트가 끝나면 AI별로 **"사람 같았음" 1~5점 + 한 줄 의견**을 남길 수 있게 한다(건너뛰기 가능). 신고 버튼(3.14)에도 "로봇 같음" 항목을 둔다.
- 점수와 의견은 파일로 내보내 Claude Code가 튜닝에 쓴다. 사람 데이터가 없으니 **성진 님의 체감이 기준**이다.
- 자동 점검: 솔버 외 성향에서 습관을 지킨 비율이 설정값 근처인지, 같은 상황 반복 시 행동이 지나치게 섞이거나 지나치게 단조롭지 않은지.

### 3.8 상대 착취는 하지 않음 + 단순 기억 반응 [확정]

- **통계로 특정 상대의 약점을 찾아 파고드는 기능은 만들지 않는다.** (구현 난이도 대비 효과가 낮다고 판단)
- 플레이어 통계(VPIP, PFR 등)는 **복기·내 통계 화면용으로만** 수집하고, AI 판단에는 쓰지 않는다.
- 대신 사람이 실제로 하는 **짧고 감정적인 기억 반응**만 넣는다. 계산이 거의 없는 규칙이다.
  - 쇼다운에서 누군가의 블러프를 봤다 → 그 사람에게 몇 핸드 동안 콜을 조금 더 자주 (괘씸함)
  - 큰 벳 뒤에 넛을 보여준 사람 → 그 사람의 큰 벳에 몇 핸드 동안 더 잘 접음 (겁먹음)
  - 나를 크게 이긴 사람 → 틸트 상태면 그 사람과의 팟에 더 무리해서 들어감
- 반응 강도와 지속 핸드 수는 성향의 `recall`로 정한다. 솔버는 0. 이 기능은 설정에서 끌 수 있다.
- 이건 "상대를 분석"하는 게 아니라 "방금 본 장면에 흔들리는" 것이라, 착취와 달리 오히려 AI의 약점이 된다. 그게 사람답다.

### 3.9 토너먼트 인식

- 유효 스택(BB 단위)으로 3.4의 스택 구간을 고른다. 블라인드가 오르면 자동으로 플레이 방식이 바뀐다.
- [확인 필요] 순위별 보상(예: 시즌 랭킹 포인트)을 정하면 ICM(순위 상금 압박)을 넣을 수 있다. 10명 이하면 Malmuth–Harville 방식으로 빠르게 계산 가능. 순위 보상이 없다면 칩 기준만으로 충분하다 → **2차 확장.**

### 3.10 속도 예산

| 단계 | 목표 시간 (중급 폰) | 방법 |
|---|---|---|
| 프리플랍 | < 1 ms | 표 조회 + 시그모이드 |
| 포스트플랍 | < 50–80 ms | 버킷 에퀴티 1회 + 캐시, 리버·턴은 전수 계산 |
| 레인지 갱신 | < 10 ms | 1,326 콤보 가중치 곱 |

- AI 계산은 **Web Worker**에서 돌려 화면이 멈추지 않게.
- 무거운 데이터(핸드 순위, 푸시/폴드 표)는 오프라인 스크립트로 미리 만들어 JSON으로 포함.
- 순수 JS로 부족하면 그때 핸드 평가기만 WASM으로 바꾸는 걸 검토(1차는 불필요할 가능성이 높음).

### 3.11 AI 검증: 셀프플레이

Claude Code가 **화면 없이 AI끼리 토너먼트를 수천 번 돌리는 시뮬레이터**를 만든다.

- 각 성향의 실제 VPIP·PFR·AF가 3.6 목표 범위에 들어오는지
- 기대 순위: 솔버·레귤러가 장기적으로 초보·콜링스테이션보다 성적이 좋아야 함
- 규칙 위반 액션(최소 레이즈 미만 등)이 0건인지
- 칩 총합이 항상 보존되는지(칩이 생기거나 사라지면 버그)
- 시작 핸드 분포 통계 검사(2.4)
- 결정 시간 분포(속도 예산 초과 여부)
- **3.12 금지 행동 발생 0건**인지, 그리고 기대값 손실이 가장 컸던 행동 상위 목록을 뽑아 사람이 직접 훑어보며 "이건 아니다" 싶은 게 있으면 금지 규칙에 추가

### 3.12 말도 안 되는 플레이 방지 (안전장치)

3.7의 온도 공식(softmax)만 쓰면 모든 행동에 아주 작은 확률이라도 남는다. 수천 핸드를 치면 그 작은 확률이 실제로 터져서 "AA 폴드" 같은 장면이 나올 수 있다. 그래서 주사위를 굴리기 직전에 두 겹으로 막는다.

**① 절대 금지 규칙 (하드 가드)**: 어떤 성향·틸트 상태에서도 확률 0

1. 체크할 수 있는데 폴드
2. 질 수 없는 패(넛, 이미 확정 승리)로 폴드
3. 프리플랍에서 AA 폴드
4. 리버에서 상대 추정 레인지의 어떤 핸드도 이길 수 없는 패로 콜 (블러프 캐치도 불가능한 콜)
5. 스택 대부분을 이미 팟에 넣었고, 남은 콜 금액이 팟에 비해 아주 작은데 폴드 (예: 팟 오즈상 필요 승률이 5% 미만)
6. 엔진상 불가능한 행동 (최소 레이즈 미만 레이즈 등) → 엔진이 거부하고, AI 쪽 버그로 기록

**② 꼬리 자르기**
- 확률이 기준(예: 3%) 미만인 행동은 0으로 만들고 나머지를 다시 100%로 맞춘다.
- 그리고 가장 좋은 행동보다 기대값이 **팟의 일정 비율 이상 나쁜 행동**은 후보에서 뺀다. 이 비율은 실력이 낮은 성향일수록 조금 넓게.

**③ 의도된 실수와 말도 안 되는 플레이는 다르다**

| 구분 | 예 | 허용 |
|---|---|---|
| 정석 범위 안의 혼합 | 미들페어로 콜할지 폴드할지 섞기, 같은 패로 가끔 체크·가끔 벳 | 모든 성향 |
| 사람다운 실수 (성향별 약점) | 콜링스테이션이 약한 원페어로 리버까지 콜, 니트가 3벳에 너무 자주 폴드, 매니악의 과한 블러프 | 해당 성향만, 정해진 범위 안에서 |
| 말도 안 되는 플레이 | AA 프리플랍 폴드, 넛 폴드, 공짜 체크를 두고 폴드 | **어떤 성향도 금지** |

- 매니악이나 초보도 "실제로 그런 사람이 펍에 있을 법한" 수준까지만 이상하게 둔다.
- 기준 숫자(3%, 5%, 팟 대비 비율)는 초기값이다. 셀프플레이 결과를 보고 조정한다.

### 3.13 AI 품질 로드맵 [확정: 이 프로젝트에서 가장 공들이는 부분]

**원칙 다섯 가지**

1. **측정이 먼저.** 잴 수 없으면 좋아졌는지 알 수 없다. 평가 체계(3.14)를 AI v1과 **같이** 만든다.
2. **무거운 계산은 미리, 게임 중에는 조회만.** 개발 PC에서 몇 시간 걸려도 되는 계산을 미리 돌리고, 결과를 압축 데이터로 앱에 넣는다. 폰에서는 찾아보기만 한다.
3. **고민 시간 = 계산 예산.** 화면에 보이는 고민 연출(0.5~4초) 동안 실제로 더 깊게 계산할 수 있다. 큰 결정일수록 사람도 오래 고민하니 자연스럽고, 그 시간에 리버 상황을 실제로 푼다(v4). 시간이 다 되면 그때까지의 최선 결과를 쓴다.
4. **AI는 독립 모듈.** 화면 없이 명령줄(CLI)로 돌릴 수 있게 만든다. Claude Code가 UI를 건드리지 않고 AI만 반복 개선할 수 있다.
5. **버전 관리.** AI v1, v2…를 나란히 보관하고, 새 버전은 3.14 기준을 통과해야 기본 AI를 교체한다.

**버전별 계획**

| 버전 | 내용 | 무엇이 좋아지나 |
|---|---|---|
| **v1** (프로토타입) | 3.4~3.12: 표 + 에퀴티 계산 + GTO 공식 + 성향 + 안전장치 | 기본 수준의 합리적 플레이 |
| **v2** 사전계산 강화 | 169핸드 순위 정밀화, **직접 계산한 내시 푸시/폴드 표**(헤즈업은 정확히, 3~4인은 근사), 프리플랍 수치를 셀프플레이로 튜닝 | 숏스택·프리플랍이 솔버에 가까워짐 |
| **v3** 헤즈업 포스트플랍 라이브러리 | 오픈소스 솔버로 대표 플랍들(전략이 비슷한 플랍끼리 묶어 수십~수백 개) × 주요 상황(싱글레이즈팟, 3벳팟) × 스택 구간을 **미리 풀어** 압축 저장. 게임 중에는 가장 비슷한 플랍의 결과를 찾아 내 핸드의 레인지 백분위로 맞춰 쓴다. 멀티웨이 팟은 v1 방식 유지 | 플랍 C벳·체크레이즈 등이 실제 솔버 결과에 근거 |
| **v4** 실시간 서브게임 풀기 | 헤즈업 턴·리버에서 추적해 둔 양쪽 레인지로 작은 게임 트리(베팅 크기 2~3개)를 만들어 **고민 시간 안에 CFR로 직접 푼다.** Web Worker, 필요하면 WASM. 시간 초과 시 v1~v3 결과로 대체 | 큰 팟 리버 결정이 가장 정확해짐 |
| **v5** 사람다움 상한선 완성 | 3.7 ①~⑨ 전부를 다듬기: 습관 목록 확장, 감정·기어 변화 튜닝, 성진 님 "사람 같음" 점수 반영. (상대 착취는 하지 않음, 3.8) | 실력은 그대로, 상대하는 느낌이 사람에 가까워짐 |

> ICM(3.9)은 순위 보상을 두기로 정할 때만 별도로 추가한다.

**오픈소스 솔버 참고 (v3용, 조사 결과)**

- 후보 1: TexasSolver (C++). 라이선스 AGPL-3.0.
- 후보 2: postflop-solver (Rust). 브라우저용 GTO 솔버 WASM Postflop의 엔진이고, Discounted CFR 알고리즘을 쓴다. 라이선스 AGPL-3.0. 2023년 10월부터 개발이 중단된 상태.
- **라이선스 주의**: AGPL 코드를 앱에 직접 넣으면 앱 소스 전체를 같은 조건으로 공개해야 할 가능성이 크다. 개발 PC에서 데이터를 만드는 데만 쓰면 앱 코드에는 섞이지 않는다. 다만 이건 법률 판단이 아니므로, 실제로 쓰기 전에 라이선스 조항을 직접 확인한다.
- v4의 실시간 풀이는 **직접 구현을 권장**한다. 리버 서브게임 정도 크기의 CFR은 직접 만들 만하고, 라이선스도 깔끔하다.
- v3의 사전계산 규모(풀어야 할 상황 수, 계산 시간, 데이터 용량)는 아직 추정 전이다. v3 시작 시 소규모로 먼저 돌려 보고 정한다.

### 3.14 AI 평가 체계 (3.11 확장)

1. **AI 시험지 (스팟 테스트)**: 특정 상황 + 성향별 기대 행동 범위. 예 (솔버·레귤러 기준):
   - 100BB, 6인, 앞에서 모두 폴드, BTN에서 AA → 레이즈 100%
   - 같은 상황에서 72o → 폴드 95% 이상
   - 리버에서 넛, 상대가 벳 → 폴드 0%, 레이즈가 일정 비율 이상
   - K72 레인보우 플랍, 프리플랍 레이저가 인포지션 → C벳 빈도 높음, 작은 사이즈
   - 리버에서 팟 크기 벳을 받은 블러프 캐처 → 레인지 전체 수비 빈도가 MDF(50%) 근처
   - 유효 8BB, BTN, 앞에서 모두 폴드, A9o → 올인
   - 처음 30개 이상으로 시작해서 계속 늘린다. 새 버전에서 기존 문항이 틀리면 **퇴보**로 본다.
2. **듀플리케이트 대결 (운 줄이기)**: 같은 카드 배열을 좌석만 바꿔 여러 번 돌린다. 패 운이 상쇄돼서 적은 핸드 수로 실력 차를 잴 수 있다.
   - 새 버전 vs 이전 버전, 성향 간 서열(솔버·레귤러 > 초보·콜링스테이션) 확인
   - **레벨 서열 확인**: 같은 성향에서 레벨만 바꿔 대결 → 레벨이 높을수록 이겨야 한다. 뒤집히는 구간이 있으면 레벨 파라미터를 고친다. 난이도 이름이 실제 체감과 맞는지의 근거
   - 지표: 100핸드당 BB 이득(bb/100)과 신뢰구간, 토너먼트 평균 순위
3. **약점 노출 정도 측정 (exploitability, 작은 상황에서)** — AI가 상대를 착취하는 기능이 아니라, AI 자신이 얼마나 공략당하기 쉬운지 재는 지표: 리버처럼 작은 상황에서 "AI 전략을 완전히 알고 최선으로 대응하는 상대"가 얼마나 이길 수 있는지 계산한다. 낮을수록 GTO에 가깝다. GTO봇 성향의 핵심 지표.
4. **성향 통계 목표**: 3.6의 VPIP/PFR/AF에 3벳%, C벳%, 쇼다운 비율 추가.
5. **사람다움 점검**: 같은 상황을 반복했을 때 행동이 너무 단조롭지 않은지, 고민 시간 분포, 3.12 금지 행동 0건.
6. **사람 피드백 루프 (가장 중요한 통로)**: 복기 화면에 **"이 AI 행동 이상함" 신고 버튼**을 둔다.
   - 누르면 그 순간의 PlayerView, AI 판단 메모, 한 줄 의견을 저장한다.
   - 신고 목록을 파일로 내보내 Claude Code에 주면, 원인을 분석하고 **시험지 문항으로 추가**한 뒤 고친다.
   - 성진 님이 직접 쳐 보면서 AI를 키우는 방법이다.
7. **AI 판단 로그 뷰어 (개발용)**: 한 결정에 대해 에퀴티, 추정 레인지, 후보별 EV, 최종 확률, 안전장치 적용 여부를 한눈에 본다.

2. **테이블 UI + 토너먼트**: 반응형 테이블(6/8/10인), 무작위 첫 버튼, 슬라이더 조작, 블라인드 레벨·남은 시간·일시정지, 탈락·순위, 게임 포기, "지금 핸드 강조하기", 자동 저장, 파일 내보내기/불러오기.

4. **스타일 + 사람다움 + 셀프플레이 튜닝 + 복기 화면**: 성향 7종, 온도·틸트·고민 시간·버릇, 시뮬레이터로 수치 맞추기. 핸드 리플레이어·필터·내 통계·"AI 기준" 비교.
5. **확장**: 텍스트 히스토리 외부 호환, 리엔트리, PWA 마무리.
6. **AI 반복 개선 (프로토타입 이후 주력)**: 3.13의 v2 → v3 → v4 → v5. 각 버전마다 3.14 평가 통과 후 교체. 사이사이 성진 님의 신고 → 시험지 추가 → 수정 루프.

> 프로토타입 범위(0~4단계 중 어디까지인지)는 맨 앞 '실행 지시' C절이 기준이다.

## 7. 사용자용: Claude Code에 넣고 실행하는 방법

**컴퓨터에서 Claude Code(터미널)를 쓰는 경우**
1. 빈 폴더를 만든다. (예: `holdem-pub`)
2. 이 md 파일을 그 폴더에 넣는다.
3. 그 폴더에서 Claude Code를 실행하고 한 줄만 말한다.

```
holdem_pub_ai_overview.md 문서대로 프로토타입 만들어 줘.
```

**웹·앱의 Claude Code(클라우드)를 쓰는 경우**
1. GitHub에 빈 저장소를 만들고 이 md 파일을 올린다.
2. Claude Code에서 그 저장소를 고르고 위와 같은 한 줄을 말한다.
3. 폰에서 보려면 저장소를 Vercel 등에 연결해 미리보기 주소로 접속한다. (Claude Code에 "배포 설정도 해 줘"라고 따로 요청 가능)

**중간에 끊기면**: "이어서 해 줘" 한 줄이면 `docs/PROGRESS.md`를 읽고 이어간다.

**기본값을 바꾸고 싶으면**: 6장 표를 고친 뒤 "6장 바뀐 대로 반영해 줘"라고 말한다.
